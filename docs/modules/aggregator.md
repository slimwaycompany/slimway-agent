# Модуль: Агрегатор мессенджеров

Чат в claude.ai: «Агрегатор мессенджеров» · Файл: `docs/modules/aggregator.md`

## Назначение
Выбрать и подключить агрегатор мессенджеров (Wazzup24 или аналог) с публичным API и вебхуками: WhatsApp, Instagram, Telegram и другие каналы в одном месте. Переписка и события идут в нашу систему (CRM, воронка лидов, Скриптолог, Контроль, напоминания) и перестают зависеть от ФитБейс Чата.

## Что уже известно (из других модулей, со ссылками)
- **Чат Fitbase** (`chats.md`): ФитБейс Чат — внутренняя разработка Fitbase, публичного API у него не найдено. Вариант (а) «официальный API ФБЧ» — только через поддержку. Текст обращения в поддержку уже готов в `chats.md`.
- **Риски WhatsApp** (`chats.md`, `scriptolog.md`): раньше серый WhatsApp через QR в Fitbase банился ежедневно (сентябрь 2026). WABA сейчас закрыт ограничением Meta Business Portfolio студии по WhatsApp Commerce Policy; обычный WhatsApp на номере работает. Один номер нельзя держать в двух QR-сессиях одновременно.
- **Память аккаунта, не из репозитория:** решение по Wazzup — пробовать серый канал вместо встроенного WhatsApp Fitbase; клиенты пишут в основном первыми; массовых рассылок не планируем; раньше рассматривали свой бот-бэкенд на Render (единый вебхук-приёмник, `isEcho` для перехвата менеджером, состояние диалога в Supabase).
- **Скриптолог** (`scriptolog.md`): напоминания пробных ставятся и отменяются через EasyChat (`deleteDelayed`), токен EasyChat берётся из background. Когда переписка пойдёт через агрегатор, источник событий для Скриптолога меняется. Нужно решить, что он делает дальше.
- **CRM-лиды** (`crm-leads.md`): в карточке заявки кнопка «Написать в ФитБейс Чат»; в ленте активности — сообщения мессенджера (метка «Диалог», интеграция `fitbase_chat`); источники «WhatsApp» и «Instagram» есть в справочнике. Новые обращения должны падать в воронку «Новые заявки» (см. `crm-leads.md`, `agent.md`).
- **Контроль** (`control.md`): скорость ответа менеджеров сейчас берётся только из отчёта Fitbase «Аналитика по ФБЧ» (API чатов нет). Агрегатор может дать свои метрики времени ответа.
- **Овчарка** (`ovcharka.md`): в планах — вебхуки (Instagram, EasyChat) для алертов «новое сообщение».
- **TikTok** (`tiktok.md`): лиды из TikTok идут через Message Assistant и Leads Center → Google Таблица → Apps Script → Fitbase. Сможет ли агрегатор заменить этот поток, не проверено.
- **Instagram** (`areas/slimway-chatplace-bot.md`, память аккаунта): автоматизация Instagram уже сделана на ChatPlace (комментарий «Хочу» и приветствие за подписку). Агрегатор может дублировать эту функцию.
- **Telegram-бот клиентов** (`telegram-bot.md`): отдельный бот на вебхуке `/tg/webhook`, к агрегатору не относится.
- **Загруженное ТЗ «Multi-Tenant Inbox»** (вложение в чате, 24.11.2026): долгосрочная цель — свой агрегатор на официальных API Meta (WhatsApp Cloud API, Instagram Messaging API) без зависимости от сторонних агрегаторов. Это противоречит задаче «выбрать готовый агрегатор». Вопрос, как совместить, открыт (см. ниже).
