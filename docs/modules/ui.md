# Модуль: UX/UI — дизайн-система и оболочка

Чат в claude.ai: «UX/UI» · Файл: `docs/modules/ui.md`

## Назначение
Внешний вид и удобство всего рабочего окна: единая дизайн-система (цвета, шрифты, отступы, компоненты), мобильная версия «как приложение», оболочка (вкладки, гамбургер, меню выбора), общие компоненты интерфейса. Остальные модули отвечают за логику своих экранов, этот — за то, как всё выглядит и ощущается.
**Любое ТЗ с интерфейсом в любом модуле сверяется с «Ключевыми решениями» этого файла.**

## Ключевые решения
- **Мобильная версия — сразу в каждой задаче (04.11.2026).** Любой новый или изменённый экран сразу верстается под телефон (≤640), планшет и компьютер; задача без мобильной вёрстки не считается выполненной. Проверка `npm run check:mobile`, скриншоты 375 и 1440 в отчёте. (`CLAUDE.md` «Интерфейс», задача 34)
- **Правила этого модуля обязательны для всех ТЗ с интерфейсом (05.11.2026).** Если ТЗ другого модуля вводит новый вид кнопки, цвет, отступ или компонент — сначала решение сюда.

### Решения Сергея (05.11.2026)
- **Оценка сейчас:** выглядит «как в 2015»; мобильной адаптации по сути нет — окно просто сжато под ширину телефона. Нужна настоящая мобильная версия, а не ужатый десктоп.
- **Ориентиры по виду и удобству:** iPhone (системные приложения, «Настройки») и Telegram — списки во всю ширину, строки с иконкой и ›, крупные заголовки, листы снизу, лёгкое стекло.
- **Иконки:** единый набор линейных иконок (типа Lucide) вместо эмодзи и символов ✓✕✎.
- **Тёмная тема:** нужна (светлая по умолчанию + тёмная; токены цветов сразу под две темы).
- **Анимации:** лёгкие — быстрые переходы, выезд панелей и листов, отклик на нажатие; без «тяжёлых» эффектов.
- **«Как приложение» на телефоне — всё:** нижняя панель (4 вкладки + «Ещё»), свайп между вкладками, FAB главного действия («+ Замер», «+ Продажа», «Закрыть смену»), шапка с ☰ и боковая панель.
- **Планшет:** пока не делаем — будет отдельной задачей.
- **Шрифт:** Manrope везде (включая React-вкладки).
- **Дизайн-скиллы для Claude Code:** ставим все три — pbakaus/impeccable, nextlevelbuilder/ui-ux-pro-max-skill, shadcn-ui/ui. Источник правил для них — этот файл (`ui.md`). shadcn/ui требует Tailwind (в проекте его нет) — как использовать (подключать Tailwind или брать только паттерны компонентов) решить при сборке ТЗ.

### Бренд и стиль
- Фирменные цвета: `#02BDB6` — основной (бирюзовый), `#263CD9` — акцент (синий). (`CLAUDE.md`)
- Стиль — светлый воздушный glassmorphism. (`CLAUDE.md`) На телефоне стекло минимальное: светлый фон, без тяжёлых теней (ТЗ «дизайн-система», 05.11, не выполнено).
- Язык — русский; деньги `₸`, пробелы между тысячами. (`CLAUDE.md`)
- Никаких `alert()` / `confirm()` и новых окон — только встроенные окна и тосты. (`CLAUDE.md` «Вход и маршруты»)
- Шрифт — Manrope (подключён в оболочке и в «Агенте»). В React-вкладках пока системный — см. «Открытые баги».

### Точки перелома
- ≤640 телефон · 641–1024 планшет · >1024 компьютер. Свои значения не вводить. (`CLAUDE.md`, задача 34 ч.1)
- Мобильная раскладка экрана (аккордеоны, листы снизу) включается до 1024 включительно там, где она есть (ТЗ «дизайн-система», 05.11, не выполнено). Оболочка уже переключается на гамбургер при ≤1024 (задача 35).

### Глобальные правила вёрстки (задача 34)
- Нет горизонтальной прокрутки страницы; широкие таблицы — прокрутка внутри блока с закреплённой первой колонкой.
- Поля ввода ≥16px на телефоне (нет автозума iOS); правильные `inputmode`/`type`: телефон `tel`, суммы и сантиметры `decimal`, даты `date`.
- Зона нажатия ≥44×44 px (`.tap-target`).
- Длинные имена и суммы — перенос или «…» (`.truncate`).
- Полноэкранные контейнеры — `height:100vh; height:100dvh`; закреплённые элементы учитывают `env(safe-area-inset-*)`.
- Hover не единственный способ что-то увидеть — всё доступно нажатием.
- Графики — по ширине контейнера, на телефоне меньше подписей, тултип по нажатию.
- Страницы занимают всю ширину вкладки; боковые панели разделов — слева. (`CLAUDE.md`)
- Печать (A4: бланк замеров, закрытие смены) — вёрстку печати не трогать.

### Общие компоненты (`components/ui/`, задача 34)
- `Modal` — по центру на компьютере; на телефоне лист снизу: шапка с крестиком закреплена, содержимое прокручивается, кнопки действий закреплены снизу.
- `ResponsiveTable` — `mode="cards"`: таблица → карточки «подпись: значение» на телефоне; `mode="scroll"`: прокрутка внутри блока с закреплённой колонкой (отчёты: продажи, метрики, ЗП, загруженность). План: в карточке 2–4 главных поля крупно, остальное по «Подробнее» (ТЗ «дизайн-система», не выполнено).
- `FilterBar` — фильтры в строку с переносом; на телефоне кнопка «Фильтры (N)» → панель снизу с «Применить».
- `PageHeader` — заголовок + действия; на телефоне действия под заголовком или в «⋯».
- `MobileAccordion` — ОДИН общий компонент для Отчётов и Настроек (ТЗ «дизайн-система», не создан).

### Мобильная дизайн-система (ТЗ «дизайн-система», чат «Render проект квалификации», 05.11 — номер 36 занят crm-leads, задача НЕ выполнена)
- Общий слой для ≤1024 (токены / `mobile.css`), один для оболочки и всех вкладок, через общие классы, а не правки в каждом компоненте.
- Текст: основной 16–17 px, вторичный 14 px, заголовок экрана 20 px жирный, цифры-итоги 22–24 px. **Мельче 13 px не использовать.**
- Плотность: отступ экрана от края 12 px; между блоками 8–12 px; внутри карточки 10–12 px; строка списка 48–52 px. Без «карточки в карточке», больших белых полей и пустых зон.
- Списки во всю ширину, строка: иконка · текст · значение/бейдж · › (как «Настройки» iPhone), разделитель тонкой линией, без рамки у каждой строки.
- Кнопки: основная — на всю ширину, высота 48 px; второстепенные — текстовые. Визуально компактно, зона нажатия ≥44.
- Итоги в отчётах — плитки 2 в ряд.

### Оболочка (задачи 34, 35; `infra.md`)
- Шапка на ≤1024: ☰ слева (точка/сумма бейджей), по центру название вкладки (17 px жирный, «…»), справа кружок-инициал (36 px) с меню «Выйти». Высота шапки 52–56 px + safe-area (размеры — ТЗ «дизайн-система», не выполнено).
- Боковая панель слева ~80% ширины, фон затемнён и размыт: логотип, имя, вкладки с иконками и бейджами (активная бирюзовая), внизу «Выйти»; закрытие свайпом, по фону, Esc, выбором вкладки. Строки 52 px, иконки 24 px, текст 17 px (ТЗ «дизайн-система»).
- Меню выбора после входа: «Привет, <имя> 👋», плитки вкладок в 2 колонки (иконка, название, бейдж), те же пункты и порядок, что в панели; на 375 тоже 2 колонки.
- На >1024: вкладки сверху + боковые вертикальные кнопки (предыдущая/следующая); повторный клик по активной вкладке = её начальный экран. Порядок вкладок — `CLAUDE.md`.
- Главное действие экрана — круглая кнопка (FAB) внизу справа («+ Замер», «+ Продажа», «Закрыть смену») — решено, не сделано.
- Цель Сергея: мобильная версия должна быть удобной, а не ужатым десктопом.

### Экраны (решения из модулей)
- Отчёты ≤1024: аккордеон групп (Менеджер, Продажи, Клиенты, Маркетинг, Настройки); заголовок группы — строка 52 px: название · число отчётов · стрелка; открытые группы запоминаются (localStorage в try/catch); отчёт на весь экран с «← Отчёты», фильтры свёрнуты в «Фильтры (N)». (`reports.md`, задача 35 ч.3 — сделано только ≤640)
- Настройки ≤1024: тот же аккордеон по разделам → раздел на весь экран с «← Настройки», формы в 1 колонку. (ТЗ «дизайн-система»; сейчас ≤640 — список разделов + «← Назад»)
- Отчёт клиента на телефоне: фигура сверху ~60–70vh, зоны — номера на фигуре + список зон, попап зоны — лист снизу, ниже «Потеряно», график, замеры, InBody; мини-навигация. (`zamery.md`, задача 34–35)
- Квалификация на телефоне: 3 колонки → переключатель «Вопрос / Ответы / Резюме», Назад/Далее закреплены снизу. (`kviz.md`, задача 35)
- Касса на телефоне: шаги сверху вниз, итог и «Оплатить» закреплены снизу. Клиенты: список ↔ карточка с «← Список». Менеджер: задача — строка 52 px с галочкой справа. Замеры: зоны в 2 колонки на ≥390, 1 колонка на 375. (задача 34, ТЗ «дизайн-система»)
- `/r/:token` (ссылка клиенту) — mobile-first. `/results` (ТВ) — на телефоне счётчики столбиком.
- Скриптолог — боковая панель Chrome 320–400 px, адаптив по ширине панели.

## Открытые баги
Аудит 05.11.2026 (по коду, без проверки на устройстве). По приоритету:

**P1 — ломает единообразие и мобильную версию**
1. Общие компоненты не используются: `Modal`, `ResponsiveTable`, `FilterBar`, `PageHeader` не импортирует ни один экран. В `SettingsPage` своя локальная `Modal`; ещё 8 экранов делают свои оверлеи `position:'fixed'` (Kassa, LeadDrawer, Settings, AdminPage, CashClosing, ManagerPage, ClientPage, ReportsPage). Поэтому лист снизу, «Фильтры (N)» и карточки таблиц на телефоне по факту не работают — задача 34 ч.1 выполнена только наполовину.
2. Мобильная дизайн-система («задача 36», 05.11) не выполнена: номер 36 ушёл в crm-leads, ТЗ в очереди нет.
3. Разные точки перелома: в `index.css` — 420, 560, 600, 640, 760, 767, 768, 899, 960, 1199, 1200; в `ReportsPage` JS `innerWidth < 480`; оболочка 1023/1024, вкладки 640. На планшете (641–1024): гамбургер оболочки + десктопная вёрстка внутри вкладок.
4. Мелкий текст: `fontSize` 9–12 px ~380 раз (11 px — 101, 10 px — 48, 9 px — 5). Правило «мельче 13 не использовать» нарушено массово.
5. `alert()` / `confirm()` — 18 мест (`SettingsPage` ×8+, `ClientsPage`, `LeadDrawer`) — нарушение правила `CLAUDE.md`. Нет общего тоста и общего окна подтверждения (тост свой в `ManagerPage` и в оболочке).
6. Два шрифта: оболочка и «Агент» — Manrope, React-вкладки — системный (`-apple-system, Segoe UI`). На Windows видно при переключении вкладок.

**P2 — разнобой стилей**
7. ~1700 inline `style={{}}` (ReportsPage 482, ClientPage 251, Settings 180, Kassa 143, Clients 89). Мобильные правки задачи 34 сделаны через `!important` поверх inline-стилей — хрупко.
8. 96 разных hex-цветов; две серые палитры параллельно (slate `#64748b/#94a3b8/#e2e8f0/#f8fafc` и gray `#6b7280/#9ca3af/#e2e6ea/#f7f8fc`); красный `#ef4444` и `#dc2626`, зелёный `#16a34a` и `#22c55e`. Токены `--teal`/`--blue` есть, но `#02BDB6` захардкожен 117 раз.

10. Три разных фона: оболочка `#eef2f7`, вкладки `#f7f8fc`, часть экранов `#f8fafc`. Стекло (blur) только в оболочке, `/results` и мобильных панелях — вкладки плоские.

13. Иконки — смесь эмодзи (📷📋🔒💬⚙…) и символов (✓✕✎), выглядят по-разному на Windows/iOS/Android.
