# Модуль: Агент воронки Fitbase

Чат в claude.ai: «Агент и овчарка» · Файл: `docs/modules/agent.md`

## Назначение
Правиловый агент (без платного ИИ) для воронки «Новые заявки» в Fitbase: двигает карточки пробных, ставит задачи, считает бюджет, шлёт сводки.

## Где код
- `src/jobs` — trial, budget, daily-summary, lifecycle, inactive (дополнить точными файлами)
- модуль работы с Fitbase API — единственное место обращений к Fitbase

## Таблицы
- `agent_events` — лента действий агента (dry / боевые)
- `agent_state`, `agent_acted` — память агента
- `lifecycle_plan` — план агента жизненного цикла
- `fitbase_clients_cache`, `fitbase_leads`, `fitbase_visits`, `fitbase_operations` — кэши данных Fitbase

## Ключевые решения
- Агент пробных и модуль бюджета — боевой режим. Бюджет: 69 000 для «Новые заявки» / «Реактивация»; LTV = purchase_amount клиента для «Новички» / «Постоянные».
- Fitbase: page_size ≤ 100, пагинация, 4xx не ретраить, circuit breaker.
- Менеджер клиента = кассир, который продал. Сергей сам не продаёт.
- Агент жизненного цикла — без DRY-флага, не запускать без явной просьбы.

1. Надёжность: сторож «агент жив» (письмо, если trial не запускался 30+ мин в рабочее время), circuit breaker на повторные ошибки Fitbase, уведомления о сбоях в cron-job.org.
2. Логика агента пробных: задачи менеджеру карточки, а не всем троим; учитывать свежий комментарий менеджера; перезапись «Не пришёл» → «Записался»; покупка ≥ 40 000 → «Успех» с бюджетом = цена.
3. Правила Fitbase для менеджеров: отмены через статус «Отказался», менеджер и КК на карточке, отключить дублирующие автозадачи Fitbase.
4. Агент жизненного цикла: исправить план (60 карточек ошибочно в «Вечность», 75 «Новичков» на проверке, «Успех» → «Реактивация»), DRY-проверка, потом боевой.
