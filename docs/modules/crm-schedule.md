# Модуль: CRM — Расписание

Чат в claude.ai: «CRM: расписание» · Файл: `docs/modules/crm-schedule.md`

## Назначение
Вкладка «Расписание»: запись клиентов на аппараты по абонементам/услугам, бронь аппаратов, отметка «Пришёл» и списание сеансов.

## Где код
- `kviz/client/src/pages/crm/SchedulePage.tsx` — главная страница расписания: сетка блоков по видам аппаратов, карточки броней (badge-этикетки), форма записи, детальная модалка, SMS-диалог
- `kviz/client/src/pages/crm/SettingsPage.tsx` — `ClassesSection`: правила отмены, шаг сетки по видам, цветовые этикетки (short_name); `BranchSection`: реквизиты филиала, часы работы по дням
- `src/http/crm.ts` — API расписания (schedule/day с `crm_day_hours` RPC, client-options, free-devices, suggest, bookings CRUD), API этикеток (short_name), GET/PUT settings/classes, PATCH device-types, GET/PUT /kviz/api/crm/branch

## Таблицы
- `crm_bookings` — брони: device_id, group_id (связка фаз), client_id, client_plan_id/item_id, plan_id (для бесплатных), kind (plan/free), status (booked/confirmed/attended/no_show/late_cancel/cancelled), starts_at/ends_at UTC, session_burned, note, trainer, cancel_reason; exclusion constraint по device_id + tsrange на пересечение, exclusion по client_id + tsrange
- `crm_booking_labels` — этикетки: name, short_name (1–4 символа), color (hex), sort, is_active, is_system
- `crm_booking_label_links` — связь брони и этикеток
- `crm_device_types.grid_step_minutes` — шаг сетки в минутах (по умолчанию null → берётся session_minutes+10)
- `crm_settings`: `schedule.day_start` / `schedule.day_end` — запасной fallback когда `crm_day_hours` вернул null; `lessons.*`, `labels.*`
- `crm_branches` — реквизиты: legal_name, bin, country, city, address, phone, timezone, currency, language, socials (jsonb)
- `crm_branch_hours` — часы работы: branch_id, weekday (1–7, пн=1), is_open, open_time, close_time
- RPC: `crm_booking_create`, `crm_booking_set_status`, `crm_booking_cancel`, `crm_booking_move`, `crm_day_hours(p_date)` → (is_open, open_time, close_time)

## Ключевые решения (собраны 27.10)
- **Мобильная версия — сразу в каждой задаче (04.11.2026).** Любой новый или изменённый экран сразу верстается под телефон (≤640), планшет и компьютер; задача без мобильной вёрстки не считается выполненной. Проверка `npm run check:mobile`, скриншоты 375 и 1440 в отчёте.
- Неделя пн–вс, слева время 07:00–23:00, часовые ячейки; запись на точное время с шагом 30 мин внутри ячейки.
- Записать можно только клиента с оплаченным абонементом (оплата = продажа в Кассе). Бесплатные услуги (is_free_booking: пробное, замер) — без кассы.
- При записи: клиент → его активные абонементы (может быть несколько) с остатком сеансов и статусом активации → доступные аппараты. Один абонемент — выбирается сам. Ошибся ячейкой — запись переносится в выбранное время.
- Активная + завершающая фаза: две последовательные брони; завершающая сразу после окончания активной по времени сеанса аппарата. Нет места — предупредить и предложить ближайшее время.
- Вместимость = работающие и свободные аппараты нужного вида; маленький индикатор свободных, меняется при выборе абонемента.
- «Кто проводит» — консультанты (пока из пользователей; позже окно сотрудников).
- Сеанс списывается по отметке «Пришёл». Неявка сеанс не сжигает (`lessons.no_show_burns_session` = false), правила — галочками в Настройки → Занятия.
- Абонемент активируется первым посещением (функция активации заготовлена на этапе 2).
- Услуги (разовое посещение, замер InBody) работают похоже на абонементы — для другого отчёта.

### Решения 05.11.2026 (после разбора Fitbase)
- **Завершающая фаза — автобронь.** Если в составе абонемента есть завершающая фаза, при записи на активную система сама бронирует завершающий аппарат сразу после окончания активной. Две брони связаны: перенос и отмена — вместе. Нет места — предложить ближайшее время, где свободны оба.
- **Один клиент на один аппарат.** Пересечения броней одного аппарата запрещены на уровне базы (exclusion constraint), не только в форме. Клиент не может быть одновременно на двух аппаратах.
- **Аппарат подбирается автоматически:** свободный нужного вида и наименее загруженный за день; менеджер может сменить.
- **Доступные аппараты — из состава абонемента клиента** (`crm_client_plan_items`), никаких галочек абонементов на шаблоне занятия.
- **Отмена:** ранняя — не позже чем за 720 мин (12 ч) до начала; позже — «Поздняя отмена». Правила включает/выключает админ в Настройки → Занятия: `lessons.early_cancel_minutes` (720), `lessons.late_cancel_burns_session` (вкл/выкл), `lessons.no_show_burns_session` (false).
- **Статусы брони:** Записан, Подтверждено, Пришёл, Не пришёл, Поздняя отмена, Отменена. «Ожидает оплаты» и лист ожидания не нужны — без оплаты не записываем.
- ~~**Вид — переключатель «День по аппаратам» / «Неделя».**~~ (отменено 23.11 — только день по аппаратам, см. «Уточнённый образец») По умолчанию «День по аппаратам» (колонки = аппараты, как «По залам» в Fitbase); последний выбор запоминается у пользователя. На телефоне — день, аппараты листаются по горизонтали внутри сетки.
- **Длительность:** пробное — 20 мин; остальное — по `session_minutes` аппарата.
- **Время работы 07:00–22:00** (как график залов в Fitbase) — поправить `schedule.day_end` на 22:00.
- **Тренер** подставляется сам — залогиненный сотрудник, можно сменить.

### Образец вида расписания (скрин от Сергея, 21.11.2026 — расписание турецкой студии SlimWorld)
Так нужно собрать главный экран расписания:
- **Один экран — все виды аппаратов рядом**, блоками слева направо: VACU → INFRASTEP → INFRASHAPE → ROLL SHAPE. Экран листается по горизонтали.
- **У каждого блока своя колонка времени** («Saat») и свой шаг строк — по времени сеанса этого вида аппарата (в образце VACU и INFRASHAPE шагом 40 мин: 08:00, 08:40, 09:20…; INFRASTEP — 30 мин: 08:00, 08:30, 09:00…). Поэтому сетки блоков не совпадают по строкам.
- **Внутри блока колонки = конкретные аппараты этого вида** (в образце «1.Üye … 4.Üye»). У нас: Vacuactiv 1–3, Infrastep, Infrashape, Rollshape 1–4 — колонок столько, сколько работающих аппаратов вида.
- **В шапке блока** — название вида и кнопки: календарь (дата), фильтр/настройки, чат (написать клиентам блока).
- **Карточка брони занимает ячейку**, в ней:
  - ФИО клиента заглавными, перед ним метка «VIP» (если клиент VIP);
  - короткая заметка менеджера под именем (напр. «фото-видео нет», «12–17 удобно», «оплата 19 ноября», «вакуум и тепло снизить», «продление»);
  - строка значков: статус (✓ пришёл, ? не подтверждено, × не пришёл/отмена), оплата (значок денег), и др. метки-значки (сердце, яблоко, предупреждение и т.п.).
- **Цвет карточки = отметка/статус.** В образце: обычная (без заливки), зелёная, салатовая, голубая, фиолетовая, бежевая, тёмно-синяя/серая с плашкой, тёмно-красная (неявка/отмена — с ×). Значения цветов у нас — решить (задаёт админ в настройках).
- **Уточнённый образец (чистый макет от Сергея, 23.11.2026):**
  - Четыре блока в ряд: **VACU · INFRASTEP · INFRASHAPE · ROLL SHAPE**, каждый в своей рамке.
  - Шапка блока: название вида слева; справа три кнопки — календарь с «+» (выбор даты / добавить запись), настройки-ползунки (фильтр/настройки блока), красная кнопка «SMS» (написать клиентам блока).
  - Первая колонка «Час», дальше колонки аппаратов с заголовком в две строки: «N.» — номер аппарата, ниже «1. Клиент» (подпись слота клиента). VACU — 4 колонки, INFRASTEP — 1, INFRASHAPE — 1, ROLL SHAPE — 4. У нас колонок = работающих аппаратов вида (Vacuactiv 3, Infrastep 1, Infrashape 1, Rollshape 4).
  - Шаг строк свой у каждого блока: VACU, INFRASHAPE, ROLL SHAPE — 40 мин (08:00, 08:40, 09:20, 10:00…); INFRASTEP — 30 мин (08:00, 08:30, 09:00…).
  - Строки одинаковой высоты, сетка тонкими линиями, пустые ячейки — клик = запись.
  - **Решено 23.11:**
    - Композиция — один в один как в макете.
    - **Шаг сетки:** VACU, INFRASHAPE, ROLL SHAPE — 40 мин; INFRASTEP — 30 мин. Шаг = сеанс + 10 мин между занятиями на обслуживание аппарата. Шаг сетки — настройка у вида аппарата (по умолчанию: время сеанса + 10).
    - **Над блоками только навигация по дате:** выбор даты + кнопки «Вчера», «Сегодня», «Завтра». Других переключателей нет — режим «Неделя» и переключатель «День по аппаратам / Неделя» (решение 05.11) отменены.
    - **Заголовок колонки:** «N. Аппарат» вместо «Клиент» — колонки это наши аппараты (номер/название аппарата из Настроек).
    - **Колонки динамические:** сколько работающих аппаратов вида указано в Настройках, столько колонок в блоке. Аппарат в ремонте/выключен — колонки нет (или серая — решить в ТЗ). Блок вида без аппаратов не показывается.
- **Цветовые этикетки (уточнение Сергея 21.11):** цвет карточки — это этикетка для контроля работы с клиентом. Примеры: «Первый сеанс», «Последний сеанс», «Необходимо провести замеры», «Необходимо провести замеры тела», «Обсудить продление пакета» и другие. Список этикеток и цветов — справочник в Настройках (админ). 
  - **Решено 21.11:** пока этикеток пять: «Новый клиент» (первый сеанс), «Последний сеанс», «Замер тела», «Замер InBody», «Обсудить продление пакета».
  - **Автоматические (будущая автоматизация через модуль control — контроль менеджеров):** все пять — «Новый клиент», «Последний сеанс», «Замер тела», «Замер InBody», «Обсудить продление пакета». Продление: этикетка ставится, когда в абонементе осталось 2 занятия и меньше (решено 21.11; порог вынести в настройку). Правила замеров уже описаны в control.md (п.1 «Замеры» консультанта, решения 18.11): пробное — только InBody; первое посещение по абонементу и последнее — InBody + замер тела; InBody раз в 7 дней; абонемент > месяца — замер тела раз в 30 дней. Этикетку ставить на бронь, на которой замер обязателен, — те же правила, что у автопроверок `measure_*`, считать одним кодом.
  - На первом этапе расписания: справочник этикеток + ручная установка всех пяти; автоустановку подключаем позже вместе с control.
  - Открыто: если на брони несколько этикеток — показывать один цвет по приоритету или несколько цветных полос на карточке (предложение Claude: заливка по главной + маленькие цветные точки остальных).
- **Пробное/демо** выделено значком ⚡ и временем в тексте («⚡ 15:00 DEMO …»).
- Пустые ячейки кликабельны — запись на это время и аппарат.
- Внизу справа — текущее время.

Открыто по образцу: (1) приоритет/показ нескольких этикеток на одной брони (см. выше); (2) список значков-меток и кто их ставит; (3) что значит «VIP» у нас (галочка в карточке клиента?); (4) нужна ли отметка «(M)» — мужчина (у образца есть) — пока студия женская; (5) — снято 23.11: это единственный вид, недели нет.

### Как устроено в Fitbase (разбор 05.11.2026)
- Залы = аппараты (Infrashape, Infrastep, Rollshape 1–4, Vacuactiv 1–3), у каждого «постоянный график» 07:00–22:00 с автопродлением.
- Занятие = тип тренировки + тренер + место (аппарат) + дата/время + длительность (30, пробное 20). На каждого клиента — отдельное персональное занятие, в нём запись клиента.
- Вместимость персонального занятия 3–4 при одном аппарате; проверки пересечений нет (05.11 на Vacuactiv 1 стояли 19:00–19:30 и 19:15–19:45, одна клиентка одновременно на Vacuactiv 1 и 3).
- Завершающая фаза отдельно не бронируется (Rollshape 2 и 4 пустые неделями). Нагрузка перекошена: Vacuactiv 1 до 19 занятий в день, Vacuactiv 2–3 по 2–10.
- Какие абонементы можно записать — галочки на шаблоне занятия.
- Статусы записи: Не подтверждено, Подтверждено, Отказался, Пришёл, Не пришёл, Поздняя отмена, В ожидании, Ожидает оплаты. Ранняя отмена — 720 мин.
- Есть: перенос занятия, замена тренера, «Написать клиентам», повторение по шаблону, комментарий.
