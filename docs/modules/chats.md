# Модуль: Чаты (EasyChat / ФитБейс Чат)

Чат в claude.ai: «Чаты (EasyChat)» · Файл: `docs/modules/chats.md`

## Назначение
Выяснить, через что в Fitbase работают чаты с клиентками, и как получать переписку и события (новое входящее, новый диалог) в нашу систему: агент и овчарка, Скриптолог, будущая CRM с лидами и воронкой. Сейчас — этап исследования, кода нет.

## Что уже известно (перенесено из других модулей, 05.11.2026)
- Чат Fitbase = сервис EasyChat (`chat.easychat.ru`) во фрейме `#easychatIframe` на `slimway.fitbase.io`. API чатов у Fitbase нет (`CLAUDE.md` §2, `scriptolog.md`).
- Селекторы EasyChat (классы хэшированные, привязка только к устойчивым частям): поле ввода `textarea[placeholder="Введите текст сообщения"]`; имя `[class*="_name-row_"] h4`; телефон `[class*="_bio_"] [class*="_status_"]`; сообщения `[class*="_message-list_"]` / `[class*="_message-item_"]` / `[class*="_own_"]`. URL при смене диалога не меняется → только MutationObserver (`scriptolog.md`). Селекторы сообщений добавлены «по шаблону», на живом интерфейсе не проверены (открытый баг Скриптолога).
- Скриптолог уже читает переписку открытого диалога: MutationObserver → `chrome.runtime.sendMessage(chat-message)` (direction in/out) → background → sidepanel → iframe `/scriptolog`. Текст в базу не пишется. Расширение никогда не отправляет сообщения само (`scriptolog.md`).
- Каналы, которые Скриптолог различает по шапке диалога: whatsapp, instagram, telegram, vk, max, viber (`extension/selectors.js`). Был баг «unknown» у WhatsApp.
- Овчарка в планах: «Работа с вебхуками, если появятся (Instagram, EasyChat)» (`ovcharka.md`). Таймеры касаний скриптолога через овчарку (`scriptolog.md`).
- CRM-лиды: в карточке заявки кнопка «Написать в ФитБейс Чат»; в ленте активности — сообщения мессенджера (WhatsApp, метка «Диалог», интеграция `fitbase_chat`) (`crm-leads.md`). Источник «WhatsApp» есть в справочнике источников.
- TikTok: в планах «тот же умный поток лидов для Instagram и WhatsApp»; ИИ-агент добавляет контекст переписки в описание карточки (`tiktok.md`).
- История WhatsApp студии (память чатов claude.ai, сентябрь 2026): раньше WhatsApp через Fitbase по QR (без рассылок) банили ежедневно; рассматривали Wazzup24 (серый канал и WABA); у Meta Business Portfolio студии ограничение по WhatsApp Commerce Policy — WABA сейчас подключить нельзя, обычный WhatsApp на номере работает; массовых рассылок не планируем, клиентки в основном пишут первыми.

## Находки исследования (05.11.2026, интернет)
- **Fitbase называет чат своей разработкой** — «FitBase Чат / ФитБейс Чат (ФБЧ) — внутренняя разработка FitBase» (help.fitbase.io, статьи 23813, 24087, 26884, 28943). Отдельной публичной компании/продукта EasyChat с документацией API для мессенджеров найти не удалось (под именем EasyChat в сети — несвязанные продукты: плагин WordPress EasyChat24, чат Wix и т. п.). Вывод-гипотеза: `chat.easychat.ru` — движок/домен самого Fitbase (или white-label подрядчика), публичного API нет. Подтвердить у поддержки.
- Подключение: Fitbase → Настройки → Интеграции → ФитБейс Чат → «Включить интеграцию» → вкладки «Каналы», «Операторы».
- **Каналы:** WhatsApp, Telegram (личный), Telegram Bot, ВКонтакте (сообщество), MAX, MAX Bot, Instagram. MAX — только на тарифе Pro.
- **WhatsApp — по QR-коду** («Связать устройство»), то есть «серое» подключение через веб-сессию, НЕ официальный WhatsApp Business API. Fitbase предупреждает: если тот же WhatsApp открыт ещё и в браузере (WhatsApp Web) — связь с чатом может рваться. Риск бана — как у любого QR-шлюза.
- **Instagram — кнопка «Авторизоваться» + «разрешите доступ к сообщениям»**, авторизация из страны, где Instagram доступен. Похоже на официальный вход Meta (OAuth), но это не подтверждено.
- **Автосоздание заявок:** при первом обращении клиента система сама создаёт заявку на нужном этапе воронки с источником. У каждого канала галочка «Не создавать заявку при первом контакте». Есть галочка «Синхронизировать сообщения из ранее добавленного канала» (перенос истории).
- **Привязка диалога к клиенту:** WhatsApp — по номеру; Telegram, MAX, Instagram телефон не передают → вручную кнопкой «Связать с клиентом» (поиск по ФИО/телефону). Есть фильтр «непривязанные к CRM чаты».
- В диалоге видна карточка клиента: статус, комментарии, теги, задачи, заявки, покупки, записи. Из чата можно создать задачу, заявку, комментарий, тег.
- Операторы, закрепление чата за оператором, смена оператора, папки, теги, архив, «спам» (удаляет навсегда), шаблоны, отложенные сообщения, триггерные и массовые рассылки (через автоматизации).
- Встроенные отчёты: «Отчёты и аналитика → Менеджеры → Аналитика по ФБЧ» (диалоги, входящие/исходящие, среднее время ответа и первого ответа, по операторам и каналам); «Маркетинг → Рассылки через ФитБейс Чат».
- Написать первым: WhatsApp по номеру, Telegram по юзернейму/номеру, ВК — только подписчикам группы, MAX по номеру (MAX часто банит, если много писать первым).
- Ни в одной статье нет API, вебхуков или выгрузки истории переписки.

## План исследования
1. **Подтвердить, что такое EasyChat** — вопрос поддержке Fitbase (текст ниже): своя разработка или подрядчик, есть ли API/вебхуки/выгрузка, планы.
2. **Кабинет студии** — Сергей открывает Fitbase → Настройки → Интеграции → ФитБейс Чат и присылает скриншоты вкладок (Каналы, Операторы, всё что есть; ищем «API», «Webhook», «Интеграции», «Выгрузка»). Фиксируем: какие каналы подключены, статусы, включена ли галочка «Не создавать заявку при первом контакте».
3. **Сетевые запросы** (DevTools, инструкция ниже) — понять, откуда фрейм берёт данные: REST или WebSocket, домен API, есть ли объекты «диалог/сообщение» с телефоном и id клиента Fitbase. Это нужно для оценки варианта (б) и для понимания, как связан диалог с клиентом. Использовать внутренний API без разрешения не планируем — только для понимания.
4. **Fitbase API v2 (у нас есть доступ)** — проверить, видно ли в лидах, созданных чатом, признак источника/интеграции (`fitbase_chat`), канал, время первого сообщения, комментарии с текстом. Если да — это уже событие «новый контакт в чате» без доступа к самому чату (вариант г).
5. **Сравнить варианты** (ниже) и выбрать: что берём сейчас (для агента/Скриптолога) и что на переезд в свою CRM.
6. **Каналы для своей CRM** — если идём в вариант (в): сравнить Wazzup24 / другой агрегатор (API + вебхуки, Instagram API, Telegram, WABA), цену, риск бана, что будет с ФБЧ (один номер WhatsApp не держать в двух QR-шлюзах одновременно).

## Варианты получения переписки и событий
- **(а) Официальный API / вебхуки EasyChat/ФБЧ.** Лучший вариант, если есть. Публично не найден → только через поддержку. Плюсы: надёжно, по правилам. Минусы: скорее всего нет или только «в планах».
- **(б) Чтение через наше расширение (как сейчас).** Плюсы: уже работает, бесплатно, бан номера не добавляет, ничего не меняем в каналах. Минусы: только пока у менеджера открыт Chrome с чатом; видно в основном открытый диалог (можно расширить на список диалогов — счётчики непрочитанных, превью последнего сообщения); хрупкие селекторы, ломаются при обновлении интерфейса; не подходит как «сервер событий» для своей CRM. Подвариант (б2) — дергать внутренний API фрейма с сервера по токену сессии: хрупко, может нарушать условия Fitbase, токены живут недолго — не рекомендую.
- **(в) Свой провайдер каналов** (Wazzup24, другой агрегатор, официальный WABA). Плюсы: публичный API и вебхуки, вся переписка у нас, основа для своей CRM и ИИ-агента. Минусы: платно; WABA сейчас заблокирован ограничением Meta Business; серый WhatsApp через провайдера несёт тот же риск бана; если увести номер из ФБЧ — теряем автозаявки, отчёты ФБЧ и карточку клиента в чате Fitbase, пока сами не переехали; держать один номер в двух QR-сессиях — риск разрывов и бана.
- **(г) Косвенно через Fitbase API.** ФБЧ сам создаёт заявку при первом контакте → агент уже видит новые лиды (опрос API). Плюсы: без новых сервисов и рисков, работает сейчас. Минусы: только факт нового контакта (и, возможно, канал), без текста и без последующих сообщений.

## Инструкция: посмотреть сетевые запросы чата (DevTools)
1. Chrome → `slimway.fitbase.io` → открыть ФитБейс Чат. Расширение Скриптолог можно не выключать.
2. Нажать F12 → вкладка **Network** (Сеть). Поставить галочку **Preserve log**. Нажать Ctrl+R (перезагрузка).
3. В поле фильтра ввести `easychat`. Сделать скриншот списка запросов (колонки Name, Status, Type, Domain — если Domain нет, правый клик по заголовку колонок → включить Domain).
4. Нажать фильтр **WS** (WebSocket). Если есть строка — кликнуть → вкладка **Messages**. Открыть любой диалог, дождаться/написать тестовое сообщение себе. Скриншот нескольких строк сообщений.
5. Нажать фильтр **Fetch/XHR**. Кликнуть по запросу, похожему на список диалогов или сообщений (`dialogs`, `chats`, `messages`, `conversations`). Скриншоты вкладок **Headers** (только верх: Request URL и Method) и **Preview** (один объект диалога/сообщения).
6. Вкладка **Elements** → Ctrl+F → `easychatIframe` → скопировать атрибут `src` фрейма.
7. **Скрыть перед отправкой:** заголовки `Authorization`, `Cookie`, `Set-Cookie`, любые `token`, `key`, `secret`, `session`, `jwt` в URL и в `src` фрейма (замазать или заменить на `***`). Телефоны и имена клиенток тоже можно замазать — нам важны названия полей, а не значения. Пароли и токены в чат не присылать.
