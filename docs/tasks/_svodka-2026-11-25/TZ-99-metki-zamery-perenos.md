═══ ЧАСТЬ 4 — Перенос записи по правам (crm-schedule, logins) ═══
- Новое право в PERM_CATALOG (`src/core/permissions.ts`), блок «Расписание»: `schedule.reschedule_future` — «Переносить запись на другой день», kind 'action', parent 'schedule.main'. Выдать в пресетах должностям управляющего и выше (`branch_manager`, `company_manager` и выше; admin — всегда).
- Правило (Сергей): продавец/менеджер с `schedule.book` переносит запись только на **сегодня** (любое свободное время текущего дня по UTC+5). На завтра и дальше — только с `schedule.reschedule_future`.
- Проверка на СЕРВЕРЕ: POST `/schedule/bookings/:id/move` и PATCH `/schedule/bookings/:id` (если меняется дата) — новая дата ≠ сегодня (UTC+5) и нет `schedule.reschedule_future` → 403 «Перенести на другой день может управляющий. Можно перенести только на сегодня».
- Отдельно: перенос записи, у которой исходная дата не сегодня (например, вчерашняя или завтрашняя), тоже требует `schedule.reschedule_future`.
- В UI: в окне переноса без права выбор даты заблокирован на «сегодня» с подсказкой.
- Отмена записи и новая запись — без изменений.
