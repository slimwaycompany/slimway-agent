═══ ЧАСТЬ 1 — QR InBody: недостающие поля ═══
- Баг: парсер не читает норму мышц (`smm_min` / `smm_max`, эталон на листе 21.4–26.2) и окружность живота (`abdomen_circumference`) — пишутся null.
- Найти позиции этих полей в строке QR (как в фиксе VFL из позиции 150, task 95), разобрать, записать. Если окружности живота в QR нет — так и написать в zamery.md, не выдумывать.
- Сверка (пункт «В работе» в листе OCR): на 3 реальных листах из базы сравнить все цифры QR с бумажным листом — вес, жир, мышцы, висцеральный жир, сегменты. Результат — таблица в `docs/reports/inbody-qr-check.md`.

═══ ЧАСТЬ 2 — QR: распознавание с первого раза ═══
- Скан с камеры: подсказка-рамка, автофокус/торч (если устройство даёт), попытки на нескольких масштабах и с повышением контраста/бинаризацией кадра; поворот кадра ±90°.
- Распознавание по фото (в том числе из галереи): то же — несколько проходов (контраст, резкость, поворот, обрезка по найденному квадрату).
- Ошибка — понятный текст: «QR не найден. Снимите ближе, без бликов» и кнопка «Ввести вручную».
- Один общий сканер (тот, что для InBody) — оформить как переиспользуемый компонент `QrScanner` для будущих штрих-кодов и EAN (ocr.md).

═══ ЧАСТЬ 3 — Прогноз по зонам (черновик, только для admin) ═══
- В отчёте клиента для role=admin — блок «Прогноз (тест)»: по каждой зоне линейный тренд по последним замерам → ожидаемое значение через 4 недели. Пометка «черновик, проверяется».
- Сергей сначала проверяет, насколько похоже на правду; клиентке и на ТВ не показывать.

═══ ЧАСТЬ 4 — ТВ: соединение и производительность ═══
- Разобраться, как экран ТВ получает обновления (SSE, polling или иначе), и сделать, чтобы он не замирал: heartbeat (для SSE — `:` комментарий каждые 25 с), автопереподключение с нарастающей паузой, перезагрузка страницы раз в сутки ночью (03:00 UTC+5), индикатор «нет связи» в углу.
- Облегчённый режим для слабых ТВ: настройка «Анимации: полные / облегчённые / выкл» в Настройках → ТВ-экран. Облегчённый — без blob-фона, blur, теней и покачивания, переходы только fade. Автоматически предлагать облегчённый, если FPS < 30 первые 20 секунд (запись в лог).
- Проверить экран на 1920×1080, 1366×768, 1280×720, 1024×768, 3840×2160 (Playwright-скриншоты в отчёт).
- Шрифт Barlow Condensed не поддерживает кириллицу — заменить для кириллицы на подходящий condensed-шрифт с кириллицей или Manrope.

═══ ЧАСТЬ 5 — ТВ: редактор слайдов ═══
- Перетаскивание элементов free-слайда мышью (и пальцем на планшете), с привязкой к сетке 8 px; числовые поля остаются.
- Предпросмотр загруженного изображения в AddSlideModal (promo/usp).
- Редактирование слайдов результатов клиентки (result1/result2) после создания: сменить клиентку, шаблон, подпись — без удаления слайда.

═══ ЧАСТЬ 6 — Telegram-бот: абонементы и посещения ═══
- В боте у привязанной клиентки — экран «Мой абонемент»: активные абонементы из нашей CRM (`crm_client_plans`, статусы 'active' / 'frozen' / 'not_activated'): название, остаток занятий по аппаратам, дата окончания (и доп. срок), заморозка; последние 10 посещений.
- Связка клиента бота с `crm_clients` — по `phone_digits` (в `crm_*` телефон только цифрами 7XXXXXXXXXX, в `body_clients` — `+7…`; не смешивать).
