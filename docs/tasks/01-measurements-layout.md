# Задача 01 — Замеры: раскладка карточки клиента, печать бланка, «Потеряно», экран результатов студии

Статус и журнал — в `docs/QUEUE.md`. Правила — `CLAUDE.md` / `AGENTS.md`.

## Контекст
- Уже вручную созданы таблицы `studio_results` (одна строка на клиента: client_id PK, from_measure_no, to_measure_no, cm_lost, kg_lost, fat_kg_lost, sent_by, sent_at) и `studio_settings` (key, value; есть key = 'mission'). SQL и миграции НЕ создавать.
- Исходники картинок: `png/body.png` (фигура), `img/bodyr.png` (бланк «Лист замеров тела», 2480×3508, колонки ДО и ПОСЛЕ).
- Сейчас в карточке клиента (`/kviz/measure/client/:id`) контент зажат в узкую колонку по центру (~900 px), из-за этого фигура уехала наверх, а подписи на ней мелкие и налезают. Печать бланка открывает новое окно и попадает на экран выбора вкладок.

## ЧАСТЬ 1 — Раскладка карточки клиента
- Страница занимает **всю ширину вкладки** (убрать узкий max-width контейнер для этой страницы; разумный максимум ~1600 px).
- Шапка: имя, телефон, ID, замеров, старт, кнопки «Бланк» и «+ Замер», чипы замеров №1…№N.
- Ниже — **две колонки уже от ширины ≥ 900 px**:
  - **СЛЕВА (~40%)** — фигура на **всю высоту рабочей области** (sticky при прокрутке), крупно. Подписи зон — по бокам фигуры с тонкими выносками к точкам: правые зоны клиента — слева от фигуры, левые — справа, центральные (шея, грудь, талия, живот, ягодицы) — распределить по сторонам. Плашки читаемые (шрифт ≥ 13 px), не налезают друг на друга и не закрывают силуэт.
  - **СПРАВА (~60%)**, сверху вниз:
    1. блок «Потеряно» (ЧАСТЬ 3);
    2. график динамики (чекбоксы зон как сейчас) — примерно верхняя половина колонки;
    3. таблица «Все замеры».
- Узкий экран (< 900 px): фигура сверху (высота ~70vh), под ней «Потеряно», график, таблица.
- На графике убрать налезающие подписи последних точек («330.0» поверх «58.0»): подпись последней точки только у одной активной линии, остальные значения — в подсказке при наведении.
- Координаты точек на фигуре (x%, y%), левая сторона клиента = правая сторона картинки: Шея 50,18 · Грудь 50,28 · Правая рука 36,30 · Левая рука 64,30 · Талия 50,38 · Живот 50,44 · Ягодицы 50,50 · Правое бедро 45,60 · Левое бедро 56,60 · Правая голень 46,78 · Левая голень 54.5,78.

## ЧАСТЬ 2 — Печать бланка без нового окна
- Причина бага: печать открывает `/kviz/measure/print` новым окном, а прямой заход на `/kviz/*` как документ редиректится на `/`.
- Сделать: после выбора «ДО: замер №…» и «ПОСЛЕ: замер №…» показать модальное окно с превью бланка с цифрами и кнопкой «Печать». По кнопке — скрытый iframe на `/kviz/measure/print?client=…&from=…&to=…&embed=1` внутри текущей страницы, дождаться загрузки картинки бланка, `iframe.contentWindow.print()`, после печати удалить iframe. Маршрут печати внутри iframe не должен редиректиться.
- `@page { size: A4; margin: 0 }`, бланк фоном на всю страницу, текст абсолютным позиционированием в % от размеров бланка (y — центр строки):
  - Имя Фамилия: x 36, y 12.3, крупно
  - ДО: дата x 20.5, y 25.3; вес x 19, y 29.5
  - ПОСЛЕ: дата x 79.2, y 25.3; вес x 77.8, y 29.5
  - Колонка «СМ» ДО — центр x 29.7; колонка «СМ» ПОСЛЕ — центр x 88.5
  - Строки: 1 Шея 37.7 · 2 Грудь 41.8 · 3 Левая рука 45.9 · 4 Правая рука 50.0 · 5 Талия 54.2 · 6 Ягодицы 58.3 · 7 Левое бедро 62.4 · 8 Правое бедро 66.5 · 9 Левая голень 70.6 · 10 Правая голень 74.8
  - Нижние строки (x от 12, y над линией 78.4 / 81.0 / 83.6): «Живот: 86.5 → 82.0 (−4.5 см)», «Итого: −11.0 см, вес −3.1 кг за 28 дней», «Консультант: Вера»
- Проверить в предпросмотре печати Chrome, что цифры попадают в клетки.

## ЧАСТЬ 3 — Блок «Потеряно»
- Заметная плашка справа сверху: «Потеряно со старта» (с №1 по последний замер): сантиметры (сумма обхватов) крупно «−90.0 см», вес «−3.0 кг», жир «— (появится после подключения InBody)».
- Кнопка «Отправить в результаты студии»:
  - `POST /kviz/api/measure/clients/:id/results` → upsert в `studio_results` (client_id, from_measure_no = 1, to_measure_no = последний, cm_lost и kg_lost — положительные числа потерь, fat_kg_lost = null, sent_by = display_name, sent_at = now()).
  - Если потерь нет (рост) — кнопка неактивна с подсказкой.
  - После отправки: «✓ В результатах студии: −90 см, −3 кг (17.10, Вера)». Повторная отправка обновляет строку клиента, не добавляет новую.
- В «Отчётах» замеров — колонка «В результатах» (✓ / —).

## ЧАСТЬ 4 — Экран «Результаты студии» (для будущего ТВ)
- Страница `/results?key=…` без входа; ключ из env `RESULTS_DISPLAY_KEY`, без верного ключа — 404. Только суммы, никаких имён. Не редиректить на `/` (это исключение из правила Sec-Fetch-Dest).
- Полноэкранный glassmorphism в фирменных цветах: логотип (текстовый SlimWay; если появится `img/logo.png` — показывать его), миссия из `studio_settings.mission`, три больших счётчика: «Сантиметров убрали» (сумма cm_lost), «Килограммов сбросили» (сумма kg_lost), «Жира сожгли, кг» (сумма fat_kg_lost; пока 0 — подпись «скоро с InBody»), ниже мелко «клиенток с результатом: N».
- Числа анимированно докручиваются, автообновление раз в 60 с. `GET /api/results/summary?key=…` — агрегаты.
- Админ в «Настроить» может изменить текст миссии.

## ЧАСТЬ 5 — Проверка, коммит, пуш
- Карточка клиента на 1440 / 1024 / 375: фигура слева на всю высоту, справа «Потеряно» → график → «Все замеры». Приложить скриншоты.
- Печать: выбор ДО/ПОСЛЕ → превью с цифрами → окно печати Chrome, без перехода на экран выбора. Скриншот превью.
- «Отправить в результаты студии» → `/results?key=…` показывает суммы; повторная отправка не удваивает.
