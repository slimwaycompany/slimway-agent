ЗАДАЧА 107 — План-факт (срез): считать по продавцу, а не по менеджеру лида
═══════════════════════════════════════

Перед началом прочитай CLAUDE.md, docs/STATE.md, docs/modules/reports.md (раздел «Следующее», запись 26.11.2026), docs/QUEUE.md. Сохрани ТЗ в docs/tasks/107-reports-plan-fact-seller.md и добавь в очередь.

═══════════════════════════════════════
ЧАСТЬ 1 — Сервер: GET /kviz/api/metrics/plan-fact
═══════════════════════════════════════
Файл: src/http/metrics.ts.

- Сейчас строка среза = `clMgr(o.cid, clm)` (менеджер последней карточки лида). Заменить на продавца.
- Продавец = `OrderRow.cashier` (`fitbase_operations.cashier` = `created_by_user.full_name`). Это тот же ключ, что в `metrics_seller_plan.seller`, в «Метриках по дням» и в ЗП (`payroll.ts`).
- Продажи: продавец = `o.cashier`.
- Возвраты: вычитаются у продавца ИСХОДНОЙ продажи. Сделай карту `itemId → cashier` по продажам, как `itemToOriginal` в `src/http/payroll.ts`. Если исходную продажу не нашли в выборке месяца — догрузи продажи по этим `itemId` из `fitbase_operations` (op_type <> 'refund', amount > 0) без ограничения по дате. Не нашлась и так — берём `o.cashier` возврата.
- Тип исходной продажи (новые/продления) для возврата берётся тоже из исходной продажи, как в payroll.
- `buildClientLeadMap()` в этом эндпоинте больше не нужен — убрать вызов, если он нигде больше в обработчике не используется.
- Продажи без продавца (`cashier` пустой) — только в строке ОТДЕЛ, отдельной строкой не показывать.
- Скрытые продавцы (`fin_staff.hidden` через `getStaffMap()`) — как сейчас: в ОТДЕЛ входят, своей строки нет; `has_hidden_sellers` считать по продавцам.
- План продавца — `sellerPlans.get(seller)` (как сейчас). Продавец, у которого есть план, но нет продаж в месяце, тоже выводится строкой (факт 0).
- В ответе поле `managers` переименовать в `sellers` (поле `name` в строке оставить). ОТДЕЛ (`dept`) считается как сейчас — по всем продажам.
- Имена в строках — как в других отчётах: `display_name` из `getStaffMap()`, если есть, иначе имя Fitbase. Ключ для плана — имя Fitbase.

ЧАСТЬ 2 — Клиент: PlanFactSection
═══════════════════════════════════════
Файл: kviz/client/src/pages/reports/ReportsPage.tsx.

- Интерфейсы: `PlanFactData.managers` → `sellers`; `PlanFactMgr` переименовать в `PlanFactSeller`.
- Заголовок первой колонки в обеих таблицах («1. КТО В ПЛАНЕ» и «ФАКТ ПО ШАГАМ»): «Менеджер» → «Продавец».
- Подпись в шапке: «… на менеджера» → «… на продавца».
- Сноска: «* сумма строк менеджеров может не совпадать с ОТДЕЛОМ (есть скрытые продавцы)» → «* сумма строк продавцов может не совпадать с ОТДЕЛОМ (есть скрытые продавцы или продажи без продавца)».
- Preview-режим и печать — тоже на `sellers`, подписи те же.
- Мобильная вёрстка не меняется, проверь только, что новые подписи не налезают на 375 px. Цвета — только токены, новых hex не добавлять.
