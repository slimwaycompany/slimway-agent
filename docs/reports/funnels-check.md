## DRY-флаги (конфиг / Render → Environment)

| Модуль | Env | Значение по умолчанию | Статус |
|--------|-----|-----------------------|--------|
| trial | `TRIAL_AGENT_DRY_RUN` | `true` | Установить в `false` для боевого режима |
| budget | `BUDGET_DRY_RUN` | `true` | Установить в `false` для боевого режима |
| inactive | `INACTIVE_DRY_RUN` | `true` | Установить в `false` для боевого режима |
| lifecycle | `LIFECYCLE_DRY_RUN` | `true` | Заблокирован навсегда (guard в `/run/lifecycle-plan`) |

Все 4 флага по умолчанию `true` — агент ничего не записывает в Fitbase без явного включения.

## Детали по каждому активному job-у

### trial — пробные тренировки

- Читает лидов с `funnel_step_id=3` (Записался) и `funnel_step_id=52` (Визит подтверждён).
- Сматчивает с визитами Fitbase (`/training-group-client`) по дате.
- Если пришёл — переводит в этап `STAGE_DECISION` (50).
- Если не пришёл — переводит в `STAGE_NOSHOW` (55).
- В DRY только логирует (`dry: true` в `job_runs`), Fitbase не трогает.
- **Риск**: при `STAGE_BOOKED=3` и `STAGE_CONFIRMED=52` — если у клиента одновременно два визита за день, обработается первый. Edge-case: маловероятен.

### budget — поле budget у лида

- Берёт всех активных лидов (`/lead?page_size=100`, пагинация).
- Для каждого определяет воронку через `getLeadFunnel()`.
- Воронки 2, 3 → бюджет = LTV (сумма визитов из `/training-group-client`).
- Воронки 1, 4 → фиксированное значение из `BUDGET_DEFAULT` (конфиг).
- Этапы в воронке при этом **не меняются** — только поле `budget`.
- **Наблюдение**: лиды на этапе `0` (нераспределённые) считаются в воронке 1 (`UNSORTED_DEFAULT_FUNNEL=1`). Если их много — бюджеты могут быть занижены (нет истории визитов).

### inactive — неактивные клиенты

- Пороги: `INACTIVE_DAYS_1=7`, `INACTIVE_DAYS_2=10`, `INACTIVE_DAYS_OWNER=14` (дефолты).
- Stage 7 (7+ дней): задача менеджеру.
- Stage 10 (10+ дней): задача всем.
- Stage 14 (14+ дней): задача руководителю + ретроспективное закрытие stage7/10.
- **Не перемещает** лидов в воронке — только создаёт задачи в Fitbase.
- В DRY задачи не создаются, эпизоды записываются с `stage7_dry=true`.

### lifecycle-plan

- Читает этапы трёх воронок: «Новые», «Постоянные», «Реактивация».
- Перемещает клиентов по шагам в зависимости от даты последнего визита.
- **Полностью заблокирован** guard-ом в `src/index.ts`:
  ```
  if (isDry('lifecycle')) { res.json({ status: 'dry_run' }); return; }
  ```
- Чтобы включить, надо добавить `LIFECYCLE_DRY_RUN=false` в Render Environment.

## Что не делает ни один job

| Ситуация | Статус |
|----------|--------|
| Лиды без воронки (`purchase_funnel = null`, `step.id = 0`) | budget обрабатывает как воронку 1; trial и inactive пропускают |
| Воронки 5+ (если есть) | Ни один job не затрагивает |
| Возвраты / отмены контрактов | Нет job-а; только probe-contracts читает |
| Дубликаты лидов (один клиент в двух воронках) | Не обрабатываются; агент не дедуплицирует |

## Подозрительное / требует внимания

1. **lifecycle-plan** реализован, но всегда DRY. Если его активировать — нужно сначала проверить на тестовых лидах.
2. **inactive**: при `INACTIVE_DRY_RUN=false` создаёт задачи в Fitbase для _всех_ клиентов с отсутствием ≥ 7 дней, включая тех, кто взял паузу. Рекомендуется проверить `WATCH_EXCLUDE_CLIENT_IDS` перед включением.
3. **budget**: для воронки 1 `DEFAULT_FUNNELS` — устанавливает фиксированный бюджет из конфига. Если значение не задано или `0`, может сбрасывать реальный бюджет лидов.
4. **trial**: нет обработки пробных с несколькими записями за день (берётся только первая).
